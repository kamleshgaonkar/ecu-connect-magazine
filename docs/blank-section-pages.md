# Automatic blank section pages

New sections created through **Add section** now contain one empty first story with an explicit `pagePair` setting. That story generates a fixed Opening Page and Continuation Page in the existing shared preview/PDF pipeline. Its headline, subheadline, author, blocks and media start empty; no sample copy, images, grid placements or placeholder elements are added to either page body.

The three supplied reference compositions are represented by:

- White Opening Page: gray ordinal, black section name and yellow top accent. Used for the new sections other than What's Up.
- What's Up Opening Page: black upper area, cream lower area, gray ordinal, two-line white section name and yellow accent. No headline, yellow title underline or body text from the example is inserted.
- White Continuation Page: small blue section name and yellow accent. Both pages carry the current volume/date footer and generated printed folio.

The existing bundled fonts are used; the display numerals retain the documented Bebas Neue fallback rather than claiming exact licensed-font metrics. Page dimensions remain A4 portrait. Section ordinals follow the current included-section order. Names and footer metadata are read from the current issue, while folios and contents references use actual measured pagination. The opening page is referenced in Contents without inserting an empty story bullet or placeholder headline. All contents pages remain immediately after the cover.

Only the new, explicit story setting enables this behavior. Existing sections/stories, page masters, saved grid assignments, manual blocks and legacy validation remain intact. No migration adds page pairs to old sections. Blank titles are accepted only for explicitly marked page-pair stories; empty legacy titles are still rejected. This step adds no content editors, grid controls or template-registry entries and makes no changes to the approved three-column layout. Existing controls and their stored data are retained. The prior approved basic-grid presentation was preserved separately in commit `3fa861d` before this change.

Validation:

- Typecheck, lint and production build passed.
- 63 unit tests, including all seven section types, empty content, migration compatibility, numbering and persistence.
- Nine targeted browser/rendering checks passed for Add section, both preview pages, section rename/reorder, volume/date changes, save/reload and A4 PDF export; existing basic-grid and grid-rendering checks are retained.
- Direct baseline comparison against the renderer captured at `3fa861d`: unchanged sample and populated manual-grid fixtures produced identical PDF bytes after normalizing only PDF date metadata (91,595 and 93,020 bytes in the validation environment).
- Screenshots of the white opening, black/cream opening and white continuation were captured and visually inspected against the supplied references. They can be regenerated by `tests/blank-sections.spec.ts` under `test-results/`.

No merge, deployment, external storage or Supabase change is part of this work.

## Linked Opening Page fields

Every story now supports headline, subheadline and author on its Opening Page, including regular second and later stories. Fixed section-opening designs remain limited to the existing page-pair story; later stories keep their regular page templates. In Page Builder’s Opening Page view, the corresponding three field inputs initially follow the source story fields. Editing one stores only that field in optional `openingFields`; an empty string intentionally suppresses that field. “Use story …” removes its override and resumes synchronization. Original story fields remain unchanged by these overrides, and Contents always indexes the original headline. Regular stories retain their rendering path and styles; saved display overrides also resolve in their existing linked grid fields. With no overrides, metadata continues to synchronize automatically.

The split opening places these fields in its cream lower area. Page furniture and content bodies remain unchanged; no article content, images or grid blocks are introduced. Existing visible-overflow diagnostics also apply to the opening fields and block PDF export if they exceed the fixed page area.

Follow-up validation: 64 unit tests and eight targeted browser tests passed, including all three field synchronizations and overrides, blank overrides, reset to source, save/reload, original-headline indexing, white/split rendering, blank continuations and PDF export. Typecheck, lint and production build passed.

Subsequent-story regression validation: 64 unit tests and 10 targeted browser tests passed. The first, second and third story each exercise synchronization, independent overrides, blank overrides, reset to source, original indexing, persistence and PDF export. The third story uses an existing linked grid layout and assigned article content; subsequent story pages remain regular, with only one fixed section opener. Typecheck, lint and production build passed. No stylesheet or export-route changes were required.

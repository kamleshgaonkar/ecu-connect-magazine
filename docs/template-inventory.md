# ECU Connect template inventory and approval proposal

Phase 2, 14 October 2026. Read with [the measured design system](design-system.md). **Everything described as implementation below is proposed; this phase changes documentation only.**

## 1. Inventory conventions

`PDF pN` means the physical page in the reference file; `folio` means its visible printed page number. The numbered body starts at PDF p3 / folio 1 in all four issues. Large `01–04` section markers are a separate system. For every body page before the back page, folio equals PDF index minus two. The final page visibly prints a folio only in V15.

The inventory separates constrained **page templates** from **content components**. Templates can share components without becoming a freeform canvas. Theme and continuation variants are parameters; images and article content are data. Keep the existing seven sections optional and reorderable. Original examples establish composition, not authorization to reuse their historical content as newly approved copy.

## 6. Proposed implementation plan — approval required before work starts

The existing Next.js application remains the foundation. Extend the magazine domain/editor/rendering pipeline; preserve issue creation, section/story editing, enable/order controls, explicit save/reload, local persistence, preview and PDF export. A complete dashboard/editor visual rebuild, Supabase integration and deployment are outside this proposal.

### Step 1 — Approve reference baseline and asset package

Recommended acceptance baseline: V20 for the overall magazine, supplemented by V15's dark cover-feature/transcript variants, V17's leadership/media and dense tables, and V19's office/map/lavender-gallery variants. Obtain approved ECU logo/wordmarks, cover/feature photography, shared dashboard/beach/back-page artwork, QR destinations and usable font files/licenses. Record which assets may be used in sample previews; retain fictional/not-approved labels on demo content. Do not infer asset reuse rights, chart data or new announcements from the reference PDFs.

Deliverable: a reviewed theme/type/asset manifest and reference-page acceptance list. Exact reconstruction remains limited without approved master assets/fonts. The originals' low-resolution placed graphics may suffice for reference analysis but do not replace print-quality masters.

### Step 2 — Add versioned editorial and asset fields without breaking old issues

Extend `src/domain/issue.ts` with additive/defaulted cover configuration, issue theme and folio policy, optional contribution-page data, story category/template/theme, local asset identifiers, structured portrait/quote/gallery/figure/callout/table blocks, and constrained break/keep hints. Preserve existing text blocks and IDs.
